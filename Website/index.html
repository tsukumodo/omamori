アバター改変おまもりアバターを送り出す前に、そっとひと目。

VRChatアバターをアップロードする前に、ありがちな設定ミスをまとめて見つけてくれるUnity Editor拡張です。チェックはボタン一つで走り、見つかった問題はオブジェクトを選んで中身を確かめられます。直せるものはその場で直せるので、公開してから気づいて青ざめる場面を減らせます。

VCC(VRChat Creator Companion)でこのリスティングを開き、プロジェクトに追加します。導入済みでない方は、「三つの道」から他の方法もお選びいただけます。

  • 無料
  • MIT License
  • MA対応(任意)
  • Unity 2022.3〜

おまもりが見ているもの

チェックを実行すると、下記の項目を一つずつ確かめていきます。🔍 見つかった問題はオブジェクトを選んで直接確認でき、直せるものはボタン一つで直せます。

  • 消えたスクリプト

    エラー

    アセットを削除したときや、他のプロジェクトからプレハブをコピーしてきたときに、参照先を失ったコンポーネントがアバターの中へ紛れ込んでしまいがちです。

    くわしく見る

    Missing状態のコンポーネントを一つずつ見つけて教えてくれます。多くは参照が壊れているだけなので自動修正で一括削除できますが、Unityの仕様上この修正だけはUndoで戻せません。

    ✓ 自動修正あり

  • ピンクのマテリアル

    警告

    シェーダーが同梱されていないアセットを使ったときや、アップデートで参照が外れたときに、マテリアルが唐突に真っピンクへ変わってしまいます。

    くわしく見る

    シェーダーが見つからないマテリアルを、アバターの中から探し出します。自動修正は用意していないので、見つかった箇所は手作業でシェーダーを差し直してください。

  • 意図しない発光

    警告

    肌にテクスチャを入れただけのつもりが、気づけばアバター全体が煌々と光り輝いていた——という声から生まれたチェックです。

    くわしく見る

    lilToonとUnity Standard系のマテリアルを対象に、Emissionがオンで実際に光っているものを見つけます(真っ黒や極端に暗いものは除きます)。ロック済みのマテリアルや対応外のシェーダーは対象外です。

    自動修正は発光だけをオフにし、色の設定は残します。同じマテリアルの他の箇所も一緒に変わり、発光を切り替える作りのアバターでは動きが崩れることもあるので、心当たりがあれば見送ってください。うっかり押してもUndo(Ctrl+Z)で戻せます。

    ✓ 自動修正あり

  • Descriptorの重複

    エラー

    アバターを複製したときや、プレハブをコピーして作業したときに、VRC Avatar Descriptorが同じ階層に増えてしまうことも少なくありません。

    くわしく見る

    アバタールート以下にDescriptorが複数ないか見て回ります。重複が3個あっても「1件の問題」としてまとめて数え、どれを残すか選ぶだけで残りを一括整理できます。

    ✓ 自動修正あり

  • トグルの行き先

    警告 エラー

    Modular AvatarのObjectToggleでは、オン/オフの対象を設定し忘れたり、うっかり自分自身を指定してしまったりする場面が意外とよくあります。

    くわしく見る

    ターゲットが空のままなら警告、自分自身を参照する自己参照ならエラーとして知らせます。設定漏れは早めに見つけておくと安心です。

    Modular Avatar が必要

  • 装飾品の設置忘れ

    警告

    アクセサリーを子オブジェクトとして入れたものの、Merge ArmatureやBone Proxyの設定を忘れたまま——という状態はよく起こります。

    くわしく見る

    Armatureを持つ子オブジェクトを調べ、Merge Armature / Bone Proxyが未設定になっていないか確かめます。ターゲット自体が未設定の場合も、あわせて拾い上げます。

    Modular Avatar が必要

  • 宙に浮いたメニュー

    エラー

    Expression Menuの階層を組み立てている途中で、MenuInstallerを挟み忘れたMenuItemが、そのまま取り残されてしまうことも。

    くわしく見る

    MenuItemの祖先をたどり、MenuInstallerにつながっていないものを見つけて知らせます。つながっていないメニューは、アップロードしても実際のメニューには現れません。

    Modular Avatar が必要

  • パラメータの空欄

    警告

    Expression Menuだけを組んでExpression Parametersの用意を忘れたり、パラメータ名を空のまま残してしまったりする——というのもよく見る光景です。

    くわしく見る

    Expression Menuが設定されているのにParametersが未設定の場合と、名前が空のパラメータが残っている場合の両方に気づかせてくれます。空のパラメータは同期帯域を無駄に消費するため、整理のきっかけになります。

  • 動かないFXレイヤー

    警告

    アップロードしたのに表情や着せ替えが反映されない——そんなときは、FXレイヤーのWeightが0のまま止まっている場合があります。

    くわしく見る

    FXレイヤーのWeightが0のままになっていないか確かめます。自動修正でWeightを1に戻すことができ、Undo(Ctrl+Z)で元の状態にも戻せます。

    ✓ 自動修正あり

  • あふれた同期容量

    エラー

    パラメータを増やしていくうちに、気づかないまま同期の上限を超えてしまい、アップロード時にエラーの壁にぶつかってしまいます。

    くわしく見る

    Expression Parametersの同期パラメータ合計ビット数が256bitを超えていないか計算して知らせます。超えたままではアップロードに失敗するため、公開前に気づけるのが利点です。

パフォーマンスもひと目で

PCとQuest/iOSそれぞれの総合ランクと、ランクを下げている項目を並べて表示します。各項目には「あと何をどこまで減らすと1ランク上がるか」の目安が付き、目標値はVRChat SDKが持つ基準をそのまま使うため、SDKの更新にも自然に追従します。

Quest/iOSで使えない要素(非対応シェーダー・Quest上で無効になるコンポーネント・Unity Constraintなど)も、件数と影響つきで教えてくれます。各項目からは、公式ドキュメントの該当ページを直接開けます。

ここに表示される数値は、Modular Avatarなどの非破壊改変ツールを適用する前の状態のものです。実際にアップロードされる最終的な値は、VRChat SDKのビルドパネルでご確認ください。

おまもりの自動修正は、シーンやアセットを直接書き換えます。ほとんどの操作はUndo(Ctrl+Z)で元に戻せますが、大切な作業の前には、シーンの保存やバージョン管理へのコミットといった、いつものバックアップ習慣もあわせてお使いください。

動作環境

  • Unity 2022.3 以降
  • VRChat SDK - Avatars 3.7.0 以降(パフォーマンス表示のConstraint項目が、SDK 3.7.0で追加された値を使うため)
  • Modular Avatar(任意 — 未インストールの場合はMA関連のチェックのみスキップされます)

三つの道

手に入れたら、Unityメニューの「Tools > アバター改変おまもり」からウィンドウを開いてお使いいただけます。ここでは、プロジェクトへの入手方法を三つご案内します。

ワンクリックでVCCにリスティングを登録する、一番早い道です。

  1. 上の「おまもりを授かる」ボタンを押す
  2. VCCが開いたら「Add」→「I Understand」の順にクリック
  3. プロジェクトを開いて「アバター改変おまもり」を追加

VCCがまだ手元にない場合は、先にVRChat公式のVCCを導入してからお試しください。

VCCの「Add Repository」にリスティングURLを直接貼り付けて登録する道です。

  1. VCCを開いて Settings → 「Packages」タブへ
  2. 「Add Repository」をクリックし、リスティングURLを貼り付け
  3. 「Add」→「I Understand」をクリックしてプロジェクトに追加

URLは上のコピー ボタンから控えられます。VCCの反応がない場合は再起動をお試しください。

VCCを使わず、BOOTHから直接ダウンロードしてUnityに取り込む道です。

  1. BOOTH商品ページ(tsukumodo-lab.booth.pm)を開く
  2. 配布ファイルをダウンロード
  3. 商品ページの案内にしたがってUnityプロジェクトに取り込む

この道はVCCの自動アップデート対象外です。新しいバージョンが出たときは、同じ手順で取り直してください。

    利用統計のお約束

    おまもりは改善のため、ごく簡単な利用統計を、あなたのPC内——プロジェクトの Library/ フォルダの中に記録します。データが自動で送信されることは一切ありません。

    記録する項目・保存場所をくわしく見る

    保存先は <プロジェクト>/Library/com.tsukumodo.avatar-omamori/usage-stats.json です。プロジェクトやLibraryフォルダを削除すれば、統計は一緒になくなります。

    なお、初回のご案内を何度もお見せしないよう、「ご案内済みかどうか」だけはUnity側の設定に覚えてもらっています。こちらはプロジェクトを消しても残りますが、中身はその一つきりで、統計は含まれません。

    記録する

    • チェック種別ごとの検出件数(例: Missing Scriptチェックが何件検出したか)
    • 修正種別ごとの自動修正の実行回数
    • チェックの実行回数
    • 日付(年月日のみ)
    • おまもりのバージョン
    • フィードバックとしてコピーした日(年月日のみ。まだコピーしていなければ記録されません)
    • 利用統計の収集を無効にしているかどうか
    • 記録データの形式のバージョン

    記録しない

    • アバター名・アバターのGUID
    • シーン名・ファイルパス
    • PC名・ユーザー名
    • 時刻(時分秒)

    Unityの Tools > つくも堂 > 使用統計を見る から、記録内容の確認や「フィードバックとしてコピー」、統計のクリア、収集の無効化・再開ができます。よろしければ、コピーした内容をつくも堂のX(@tsukumodo_lab)のDMで送っていただけると、今後のチェック項目を考える参考にさせていただきます(任意です)。🍀
